# Response Codes

Every transaction includes a `response_code` and `response_message` that indicate the outcome. These are Rolla's normalized codes — consistent across all payment processors.

## Response Structure

```json
{
  "reference": "TXN_abc123",
  "status": "failed",
  "gateway_response": "DECLINED",
  "response_code": "60",
  "response_message": "Insufficient funds",
  "failure_reason": "DECLINED"
}
```

| Field | Description |
|-------|-------------|
| `response_code` | Rolla's internal 2-digit code (see tables below) |
| `response_message` | Human-readable description of the code |
| `gateway_response` | Raw response from the payment processor |
| `failure_reason` | Raw processor decline reason (same as `gateway_response` for failed transactions) |

---

## Success (00)

| Code | Name | Message |
|------|------|---------|
| `00` | SUCCESS | Transaction approved |

---

## Pending / Referral (01-09)

These codes indicate the transaction requires further action before completion.

| Code | Name | Message | Action |
|------|------|---------|--------|
| `01` | REFER_TO_ISSUER | Refer to card issuer | Customer should contact their bank |
| `03` | PENDING_VERIFICATION | Pending verification | Wait for verification to complete |
| `04` | PENDING_3DS | Pending 3D Secure | Complete 3DS challenge |
| `05` | PENDING_OTP | Pending OTP verification | Enter OTP sent to customer |
| `06` | PENDING_CALLBACK | Pending callback | Wait for processor callback |
| `07` | PENDING_MANUAL_REVIEW | Pending manual review | Transaction under review |

---

## Card / Account Issues (20-39)

The transaction was declined due to a problem with the card or account.

| Code | Name | Message | Retryable | Action |
|------|------|---------|-----------|--------|
| `20` | INVALID_CARD_NUMBER | Invalid card number | Yes | Check card details |
| `21` | CARD_NOT_FOUND | Card not found | No | Use a different card |
| `22` | EXPIRED_CARD | Expired card | No | Use a valid card |
| `23` | INVALID_EXPIRY_DATE | Invalid expiry date | Yes | Check expiry date |
| `24` | INVALID_CVV | Invalid CVV/CVC | Yes | Check security code |
| `25` | INCORRECT_PIN | Incorrect PIN | Yes | Re-enter PIN |
| `26` | PIN_TRIES_EXCEEDED | PIN tries exceeded | No | Contact bank |
| `27` | CARD_NOT_ACTIVE | Card not activated | No | Activate card |
| `28` | CARD_LOST | Card reported lost | No | Contact bank |
| `29` | CARD_STOLEN | Card reported stolen | No | Contact bank |
| `30` | CARD_RESTRICTED | Card restricted | No | Contact bank |
| `31` | CARD_NOT_SUPPORTED | Card type not supported | No | Use a different card |
| `33` | ACCOUNT_CLOSED | Account closed | No | Use a different account |
| `35` | ACCOUNT_FROZEN | Account frozen | No | Contact bank |
| `38` | DO_NOT_HONOR | Do not honor | No | Contact bank |
| `39` | GENERIC_DECLINE | Transaction declined | No | Try a different card |

## Fraud / Security (40-59)

The transaction was blocked for security or fraud reasons.

| Code | Name | Message | Retryable | Action |
|------|------|---------|-----------|--------|
| `40` | SUSPECTED_FRAUD | Suspected fraud | No | Transaction blocked |
| `43` | VELOCITY_CHECK_FAILED | Too many attempts | Yes | Wait before retrying |
| `44` | ADDRESS_VERIFICATION_FAILED | Address verification failed | Yes | Check billing address |
| `45` | CVV_VERIFICATION_FAILED | CVV verification failed | Yes | Check security code |
| `46` | BLACKLISTED_CARD | Card blacklisted | No | Use a different card |
| `49` | BLACKLISTED_IP | IP address blocked | No | Contact support |
| `50` | HIGH_RISK_TRANSACTION | High risk transaction | No | Additional verification required |
| `51` | COUNTRY_NOT_ALLOWED | Country not allowed | No | Transaction not available in this region |
| `54` | AUTHENTICATION_FAILED | Authentication failed | Yes | Re-authenticate |
| `55` | AUTHENTICATION_REQUIRED | Authentication required | Yes | Complete authentication |
| `56` | THREEDS_FAILED | 3D Secure failed | Yes | Try again or use a different card |
| `57` | THREEDS_ABANDONED | 3D Secure abandoned | Yes | Complete authentication |
| `59` | OTP_FAILED | OTP verification failed | Yes | Request new OTP |

## Limits / Restrictions (60-79)

The transaction was declined because it exceeded a limit or restriction.

| Code | Name | Message | Retryable | Action |
|------|------|---------|-----------|--------|
| `60` | INSUFFICIENT_FUNDS | Insufficient funds | Yes | Use a card with sufficient balance |
| `61` | EXCEEDS_AMOUNT_LIMIT | Exceeds transaction limit | Yes | Reduce amount or contact bank |
| `62` | EXCEEDS_FREQUENCY_LIMIT | Exceeds frequency limit | Yes | Wait before retrying |
| `63` | EXCEEDS_DAILY_LIMIT | Exceeds daily limit | Yes | Try again tomorrow |
| `66` | BELOW_MINIMUM_AMOUNT | Below minimum amount | Yes | Increase amount |
| `67` | EXCEEDS_WITHDRAWAL_LIMIT | Exceeds withdrawal limit | Yes | Contact bank |
| `69` | CURRENCY_NOT_SUPPORTED | Currency not supported | No | Use a supported currency |
| `72` | CARD_NOT_ENROLLED | Card not enrolled | No | Enroll card for this service |
| `76` | GEOGRAPHIC_RESTRICTION | Geographic restriction | No | Not available in this location |
| `77` | DUPLICATE_TRANSACTION | Duplicate transaction | No | Check if already processed |

---

## System / Network Errors (80-89)

Technical errors — typically safe to retry.

| Code | Name | Message | Retryable | Action |
|------|------|---------|-----------|--------|
| `80` | SYSTEM_ERROR | System error | Yes | Try again later |
| `81` | ISSUER_UNAVAILABLE | Issuer unavailable | Yes | Try again later |
| `82` | NETWORK_ERROR | Network error | Yes | Check connection and retry |
| `83` | TIMEOUT | Request timeout | Yes | Try again |
| `85` | PROCESSOR_UNAVAILABLE | Processor unavailable | Yes | Try again later |
| `89` | MAINTENANCE_MODE | System under maintenance | Yes | Try again later |

---

## Processing Errors (90-99)

Request or data format errors.

| Code | Name | Message | Retryable | Action |
|------|------|---------|-----------|--------|
| `90` | INVALID_REQUEST | Invalid request | Yes | Check request parameters |
| `91` | INVALID_AMOUNT | Invalid amount | Yes | Check amount format |
| `92` | INVALID_CURRENCY | Invalid currency | Yes | Use valid currency code |
| `96` | FORMAT_ERROR | Format error | Yes | Check request format |
| `97` | MISSING_REQUIRED_FIELD | Missing required field | Yes | Provide all required fields |
| `98` | PROCESSING_ERROR | Processing error | Yes | Try again |
| `99` | UNKNOWN_ERROR | Unknown error | Yes | Contact support |

## Handling Response Codes

### Best Practices

<CardGroup cols={2}>
  <Card title="Retryable Errors" icon="rotate">
    For codes like `60` (Insufficient Funds), `83` (Timeout), or `81` (Issuer Unavailable), prompt the customer to retry or automatically retry after a delay.
  </Card>
  <Card title="Non-Retryable Errors" icon="ban">
    For codes like `22` (Expired Card), `38` (Do Not Honor), or `51` (Country Not Allowed), don't retry. Ask the customer to use a different payment method.
  </Card>
  <Card title="Customer Messages" icon="message">
    Use the `response_message` field when displaying errors to customers. It provides a clear, non-technical explanation.
  </Card>
  <Card title="Logging" icon="clipboard-list">
    Log `response_code`, `response_message`, and `gateway_response` together for debugging and support.
  </Card>
</CardGroup>

### Code Example

```javascript
async function handlePaymentResponse(response) {
  const { response_code, response_message, status } = response.data;

  if (status === 'successful') {
    showSuccess('Payment successful!');
    return;
  }

  // Retryable codes
  const retryable = ['60', '81', '82', '83', '85', '89', '98'];
  if (retryable.includes(response_code)) {
    showError(response_message);
    promptRetry();
    return;
  }

  // Card needs replacing
  const needsNewCard = ['22', '28', '29', '30', '31'];
  if (needsNewCard.includes(response_code)) {
    showError(response_message);
    promptNewCard();
    return;
  }

  // Default
  showError(response_message || 'Payment failed. Please try again.');
}
```

<Note>
  The `response_code` is Rolla's normalized code, consistent across all processors.
  The `gateway_response` contains the raw processor response for advanced debugging.
</Note>
