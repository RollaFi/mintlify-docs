## Overview

A virtual account is a **static** NGN bank account for one of your customers: its number never changes, unlike the **dynamic** account created for each [bank transfer checkout](/api-reference/bank-transfer-payment). Every transfer into it becomes a successful `bank_transfer` transaction for you. See the [Virtual Accounts guide](/virtual-accounts) for how they work.

<Note>
  Available to Nigerian businesses only. Requests from businesses in other countries return `400` with code `VIRTUAL_ACCOUNT_UNSUPPORTED_COUNTRY`.
</Note>

### Authentication

All endpoints require your **secret key**. Test keys create test accounts that are never opened at a bank.

```
Authorization: Bearer sk_live_your_secret_key
```

## Create a Virtual Account

<Card title="POST /collections/virtual-accounts" icon="building-columns">
  Open a static account for a customer
</Card>

A new account returns `201`. A customer can have several accounts, but each `reference` can be used only once: reusing one is refused with `409`, so look that account up with [Get a Virtual Account](#get-a-virtual-account) instead.

### Request Body

<ParamField body="email" type="string" required>
  Customer's email address. Identifies the customer; one customer can have several accounts.
</ParamField>

<ParamField body="first_name" type="string" required>
  Customer's first name
</ParamField>

<ParamField body="last_name" type="string" required>
  Customer's last name
</ParamField>

<ParamField body="phone" type="string">
  Customer's phone number
</ParamField>

<ParamField body="bvn" type="string">
  Customer's 11-digit Bank Verification Number. Optional; when sent it is passed to the bank to open the account, and only the last four digits are stored.
</ParamField>

<ParamField body="reference" type="string">
  Your own identifier for this account or customer (max 100 characters). Must be unique across your virtual accounts. Returned as `merchant_reference`.
</ParamField>

<ParamField body="metadata" type="object">
  Any key-value data you want stored with the account
</ParamField>

<RequestExample>
```bash cURL
curl -X POST "https://api.rollapay.com/collections/virtual-accounts" \
  -H "Authorization: Bearer sk_live_your_secret_key" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ada@example.com",
    "first_name": "Ada",
    "last_name": "Obi",
    "phone": "08031234567",
    "bvn": "22222222222",
    "reference": "cust-001"
  }'
```

### Response

<ResponseField name="data" type="object">
  <Expandable title="properties">
    <ResponseField name="reference" type="string">Rolla Pay reference for the account (`VA_...`). Use it to fetch the account and its transactions.</ResponseField>
    <ResponseField name="account_number" type="string">The 10-digit account number your customer transfers to</ResponseField>
    <ResponseField name="account_name" type="string">Name the customer sees when they enter the account number in their bank app</ResponseField>
    <ResponseField name="bank_name" type="string">Bank to select when transferring</ResponseField>
    <ResponseField name="merchant_reference" type="string">Your `reference`, if you sent one, otherwise `null`</ResponseField>
    <ResponseField name="status" type="string">`active`, or `deactivated` once you have [deactivated](#deactivate-a-virtual-account) it</ResponseField>
  </Expandable>
</ResponseField>

## List Virtual Accounts

<Card title="GET /collections/virtual-accounts" icon="list">
  List your virtual accounts, newest first
</Card>

### Query Parameters

<ParamField query="page" type="number" default="1">
  Page number
</ParamField>

<ParamField query="limit" type="number" default="20">
  Results per page (max 100)
</ParamField>

<ParamField query="search" type="string">
  Search by account number, account name, reference, your reference or customer email
</ParamField>

<ParamField query="merchant_reference" type="string">
  Only the account with exactly this `reference` (the one you sent when creating it)
</ParamField>

<ParamField query="customer_email" type="string">
  Only this customer's accounts. Exact match, ignoring case.
</ParamField>

<ParamField query="status" type="string">
  Filter by `active` or `deactivated`
</ParamField>

```bash
curl "https://api.rollapay.com/collections/virtual-accounts?customer_email=ada@example.com" \
  -H "Authorization: Bearer sk_live_your_secret_key"
```

```json Response
{
  "success": true,

  "data": {

        "account_number": "9002401234",
        "account_name": "Your Business - Ada Obi",

        "merchant_reference": "cust-001",
        "status": "active"

```

## Get a Virtual Account

<Card title="GET /collections/virtual-accounts/:reference" icon="magnifying-glass">
  Fetch one account by its `reference`
</Card>

```bash
curl "https://api.rollapay.com/collections/virtual-accounts/VA_2T5RLBWBQ8MWY3" \
  -H "Authorization: Bearer sk_live_your_secret_key"
```

Returns the same object as [Create](#create-a-virtual-account). Returns `404` if the account does not exist or belongs to the other mode.

## Deactivate a Virtual Account

<Card title="POST /collections/virtual-accounts/:reference/deactivate" icon="ban">
  Stop an account from receiving transfers
</Card>

Deactivating closes the account at the bank, so any transfer to it is declined. This is **permanent**: a deactivated account cannot be switched back on. To collect from the customer again, create a new virtual account.

The account is not deleted. It stays in your list with `status: "deactivated"`, and its transactions remain available. Deactivating an account that is already deactivated returns it unchanged.

<Note>
  A customer's bank app may still show the account name when they enter the number, but the transfer will be declined. If a transfer was already on its way when you deactivated the account and still arrives, it is recorded and credited to you as normal.
</Note>

```bash
curl -X POST "https://api.rollapay.com/collections/virtual-accounts/VA_2T5RLBWBQ8MWY3/deactivate" \
  -H "Authorization: Bearer sk_live_your_secret_key"
```

```json Response
{
  "success": true,
  "message": "Virtual account deactivated",
  "data": {
    "reference": "VA_2T5RLBWBQ8MWY3",
    "account_number": "9002401234",
    "account_name": "Your Business - Ada Obi",
    "bank_name": "NET Microfinance Bank",
    "merchant_reference": "cust-001",
    "status": "deactivated"
  }
}
```

## Webhook

Every transfer into a virtual account sends a `payment.success` webhook. It carries a `virtualAccount` object, so you can tell which customer paid:

```json
{
  "event": "payment.success",
  "data": {
    "reference": "CYRJ6TOXGHFUWPTV",
    "status": "successful",
    "amount": 5000,
    "currency": "NGN",
    "feeAmount": 75,
    "netAmount": 4925,
    "channel": "bank_transfer",
    "customerEmail": "ada@example.com",
    "customerName": "Ada Obi",
    "virtualAccount": {
      "id": "c84faf67-b039-43f4-bbd9-6d195cd7288a",
      "reference": "VA_2T5RLBWBQ8MWY3",
      "accountNumber": "9002401234",
      "accountName": "Your Business - Ada Obi",
      "bankName": "NET Microfinance Bank",
      "merchantReference": "cust-001",
      "senderName": "CHIDI OKAFOR",
      "senderAccountNumber": "0123456789",
      "senderBank": "GTBank Plc"
    }
  }
}
```

<Warning>
  A transfer is only reported once the bank has confirmed the money arrived. Use `data.reference` to deduplicate: it is the same for every delivery of the same transfer.
</Warning>
