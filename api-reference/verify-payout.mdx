## Overview

Retrieve the current status and details of a payout using its Rolla reference or the `reference` you sent when initiating it. Use this to confirm a payout has been completed, or to check on a pending payout.

## Authentication

| Header | Type | Required | Description |
|--------|------|----------|-------------|
| `Authorization` | string | Yes | Your secret key (`sk_live_xxx`) |

<Note>
No signature is required for GET requests — only the secret key.
</Note>

## Path Parameters

<ParamField path="reference" type="string" required>
  Either the payout reference returned when the payout was initiated (e.g., `PAYOUT-RP-1785413884695-X7K2M9QA4B`), or your own `reference` from the initiate request.
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  Indicates if the request was successful.
</ResponseField>

<ResponseField name="message" type="string">
  `Payout retrieved`, or the reason the request failed.
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="properties">
    <ResponseField name="reference" type="string">
      Rolla Pay payout reference.
    </ResponseField>
    <ResponseField name="merchant_reference" type="string | null">
      The `reference` you sent when initiating the payout, or `null` if you sent none.
    </ResponseField>
    <ResponseField name="amount" type="number">
      The amount debited from your wallet for this payout.
    </ResponseField>
    <ResponseField name="fee" type="number">
      The payout fee charged.
    </ResponseField>
    <ResponseField name="net_amount" type="number">
      The amount sent to the recipient.
    </ResponseField>
    <ResponseField name="currency" type="string">
      Currency code.
    </ResponseField>
    <ResponseField name="status" type="string">
      `pending`, `processing`, `completed` or `failed`. See [Payout Statuses](#payout-statuses).
    </ResponseField>
    <ResponseField name="destination" type="object">
      Where the payout was sent.
      <Expandable title="properties">
        <ResponseField name="type" type="string">
          `bank_transfer` or `mobile_money`.
        </ResponseField>
        <ResponseField name="bank_code" type="string">
          Recipient bank code. Bank transfers only.
        </ResponseField>
        <ResponseField name="account_number" type="string">
          Recipient account number. Bank transfers only.
        </ResponseField>
        <ResponseField name="account_name" type="string">
          Recipient account name. Bank transfers only.
        </ResponseField>
        <ResponseField name="phone_number" type="string">
          Recipient phone number. Mobile money only.
        </ResponseField>
        <ResponseField name="provider" type="string">
          Mobile money provider, e.g. `mtn-momo-cameroon`. Mobile money only.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="source" type="string">
      `api` for payouts made through the API, `dashboard` for withdrawals made from the dashboard.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      When the payout was initiated.
    </ResponseField>
    <ResponseField name="completed_at" type="string | null">
      When the payout completed, otherwise `null`.
    </ResponseField>
    <ResponseField name="failed_at" type="string | null">
      When the payout failed, otherwise `null`.
    </ResponseField>
    <ResponseField name="failure_reason" type="string | null">
      Why the payout failed, otherwise `null`.
    </ResponseField>
  </Expandable>
</ResponseField>

## Payout Statuses

| Status | Description | Final? |
|--------|-------------|--------|
| `pending` | Wallet debited, awaiting processor | No |
| `processing` | Sent to processor, awaiting confirmation | No |
| `completed` | Funds delivered to recipient | Yes |
| `failed` | Payout failed. Funds return to your wallet once the failure is confirmed with the processor | Yes |

<Tip>
For real-time updates, configure a [webhook](/api-reference/webhooks) instead of polling. You'll receive `payout.completed` or `payout.failed` events as soon as the status changes.
</Tip>
