## Overview

The Direct Payment API lets you process payments directly from your server. Depending on the channel, you can charge a card, initiate a bank transfer (virtual account), or accept mobile money.

**Use this when:**
- You have your own payment form and collect card details yourself
- You want to generate a virtual account for bank transfer payments
- You need full control over the checkout UI
- You're building a mobile app or custom integration

<Note>
  If you don't want to handle card details, use the [Checkout API](/api-reference/checkout-api) instead — it provides a secure hosted payment page.
</Note>

## Authentication

All requests must include your secret API key in the Authorization header:

```
Authorization: Bearer sk_live_your_secret_key
```

<Note>
  Use `sk_test_*` keys for testing and `sk_live_*` keys for production.
</Note>

## Request Body

<ParamField body="reference" type="string">
  Optional custom transaction reference. If not provided, a unique reference will be auto-generated (e.g., `TXN_gGbEEvK25eVgmgrf`). Must be globally unique across all transactions.
</ParamField>

<ParamField body="amount" type="number" required>
  The payment amount (e.g., 1000 for 1000 units of the currency)
</ParamField>

<ParamField body="currency" type="string" required>
  Three-letter ISO currency code (e.g., "USD", "NGN", "GBP")
</ParamField>

<ParamField body="channel" type="string" required>
  Payment channel: `card`, `bank_transfer`, `mobile_money`, or `ussd`
</ParamField>

<ParamField body="customer" type="object" required>
  Customer information
  <Expandable title="properties">
    <ParamField body="email" type="string" required>
      Customer's email address
    </ParamField>
    <ParamField body="name" type="string">
      Customer's full name
    </ParamField>
    <ParamField body="phone" type="string">
      Customer's phone number
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="card" type="object">
  Card details (required when channel is `card`)
  <Expandable title="properties">
    <ParamField body="number" type="string" required>
      Card number (13-19 digits)
    </ParamField>
    <ParamField body="expiryMonth" type="string" required>
      Card expiry month (2 digits, e.g., "01" for January)
    </ParamField>
    <ParamField body="expiryYear" type="string" required>
      Card expiry year (2 or 4 digits, e.g., "27" or "2027")
    </ParamField>
    <ParamField body="cvv" type="string" required>
      Card CVV/CVC (3-4 digits)
    </ParamField>
    <ParamField body="holderName" type="string">
      Cardholder name as it appears on the card
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="billing" type="object">
  Billing address (recommended for international cards to reduce declines)
  <Expandable title="properties">
    <ParamField body="address" type="string">
      Street address
    </ParamField>
    <ParamField body="city" type="string">
      City
    </ParamField>
    <ParamField body="state" type="string">
      State or province
    </ParamField>
    <ParamField body="country" type="string">
      Country code (e.g., "US", "NG")
    </ParamField>
    <ParamField body="postalCode" type="string">
      Postal/ZIP code
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="callbackUrl" type="string" required>
  URL to redirect the customer after payment completion. Query parameters `reference` and `status` (successful/failed) will be appended.
</ParamField>

<ParamField body="description" type="string">
  Optional description for the payment (max 500 characters)
</ParamField>

<ParamField body="metadata" type="object">
  Additional key-value pairs to attach to the transaction (e.g., order ID)
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  Indicates if the request was successful
</ResponseField>

<ResponseField name="message" type="string">
  Response message
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="properties">
    <ResponseField name="reference" type="string">
      Unique transaction reference (e.g., `TXN_gGbEEvK25eVgmgrf`) or your custom reference if provided
    </ResponseField>
    <ResponseField name="status" type="string">
      Transaction status: `pending`, `requires_action`, `processing`, `successful`, `failed`
    </ResponseField>
    <ResponseField name="payment_url" type="string">
      URL to redirect the customer for payment authentication (3D Secure, etc.). Only present for card payments that require redirect.
    </ResponseField>
    <ResponseField name="account_number" type="string">
      Virtual account number for bank transfer payments. Customer transfers to this account.
    </ResponseField>
    <ResponseField name="bank_name" type="string">
      Bank name for the virtual account (e.g., "NET Microfinance Bank").
    </ResponseField>
    <ResponseField name="account_name" type="string">
      Account name for the virtual account.
    </ResponseField>
    <ResponseField name="account_type" type="string">
      Type of virtual account: `dynamic` (expires after timeout).
    </ResponseField>
    <ResponseField name="amount" type="number">
      Amount to transfer (for bank transfer channel).
    </ResponseField>
    <ResponseField name="expires_at" type="string">
      ISO 8601 timestamp when the virtual account expires (e.g., `2026-07-23T12:30:00.000Z`).
    </ResponseField>
    <ResponseField name="next_action" type="string">
      Indicates the next action required when `status` is `requires_action`. Possible values: `redirect` (redirect to payment_url), `otp` (submit OTP), `pin` (submit PIN)
    </ResponseField>
    <ResponseField name="message" type="string">
      Additional message providing context (e.g., "Please enter the OTP sent to your phone")
    </ResponseField>
  </Expandable>
</ResponseField>

## Transaction Statuses

| Status | Description |
|--------|-------------|
| `pending` | Transaction has been created but not yet processed |
| `requires_action` | Additional action required (3DS, PIN, OTP) |
| `processing` | Transaction is being processed |
| `successful` | Transaction completed successfully |
| `failed` | Transaction failed |

## Next Steps

After initiating a payment, check the `status` and `channel` to determine the next step:

### Card Payment — `next_action` is `redirect`
1. Redirect the customer to `payment_url`
2. The customer completes authentication (3D Secure, etc.)
3. Customer is redirected back to your `callbackUrl`
4. Use the [Verify Transaction](/api-reference/verify-transaction) endpoint to confirm the final status

### Card Payment — `status` is `successful`
The transaction completed immediately without additional authentication.
1. Use the [Verify Transaction](/api-reference/verify-transaction) endpoint to confirm the final status

### Card Payment — `next_action` is `otp`
1. Display an OTP input form to the customer
2. Submit the OTP using the Submit OTP endpoint *(coming soon)*
3. Use the [Verify Transaction](/api-reference/verify-transaction) endpoint to confirm the final status

### Card Payment — `next_action` is `pin`
1. Display a PIN input form to the customer
2. Submit the PIN using the Submit PIN endpoint *(coming soon)*
3. The response may return another `next_action` (e.g., `otp`) — handle accordingly
4. Use the [Verify Transaction](/api-reference/verify-transaction) endpoint to confirm the final status

### Bank Transfer — `status` is `pending`
1. Display the virtual account details to the customer: `account_number`, `bank_name`, `account_name`, and `amount`
2. Show the expiry countdown using `expires_at` — the account is only valid until this time
3. The customer transfers the exact amount from their bank app to the virtual account
4. Poll the [Verify Transaction](/api-reference/verify-transaction) endpoint every 3–5 seconds to check for payment confirmation
5. Once `status` changes to `successful`, the payment is complete
6. You will also receive a [webhook](/api-reference/webhooks) notification when the payment is confirmed

<Warning>
  Bank transfer virtual accounts expire after 30 minutes by default. If the customer does not transfer within this window, the transaction will expire and a new one must be initiated.
</Warning>
