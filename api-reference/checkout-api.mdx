## Overview

The Checkout API lets you accept payments without handling card details on your server. You create a checkout session with the amount and customer info, and we return a secure checkout URL. The customer completes payment on our hosted page — which supports **card and bank transfer** — and we redirect them back to your site.

The hosted checkout page automatically shows the available payment methods based on the merchant's currency configuration. No code changes are needed from your side — the checkout URL handles it.

**Use this when:**
- You don't want to handle card details (simplifies PCI compliance)
- You want a ready-made payment page with no frontend work
- You need a quick integration (server-side only, no JavaScript SDK needed)

<Note>
  If you want full control over the payment UI and handle card details yourself, use the [Direct Payment API](/api-reference/initiate-payment) instead.
</Note>

## Flow

```
1. Your server → POST /transaction/checkout → Rolla API
2. Rolla returns checkout_url
3. You redirect customer to checkout_url
4. Customer pays on Rolla's hosted page
5. Customer is redirected to your callbackUrl with reference & status
6. Your server verifies the transaction via /transaction/verify/:reference
```

## Authentication

All requests must include your secret API key in the Authorization header:

```
Authorization: Bearer sk_live_your_secret_key
```

<Note>
  Use `sk_test_*` keys for testing and `sk_live_*` keys for production.
</Note>

## Request Body

<ParamField body="amount" type="number" required>
  The payment amount (e.g., 5000 for 5000 units of the currency)
</ParamField>

<ParamField body="currency" type="string" required>
  Three-letter ISO currency code (e.g., "USD", "NGN", "GBP")
</ParamField>

<ParamField body="customer" type="object" required>
  Customer information
  <Expandable title="properties">
    <ParamField body="email" type="string" required>
      Customer's email address
    </ParamField>
    <ParamField body="name" type="string" required>
      Customer's full name
    </ParamField>
    <ParamField body="phone" type="string">
      Customer's phone number
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="reference" type="string">
  Your unique reference for this transaction (e.g., your order ID). If not provided, one will be auto-generated. Must be unique across all transactions.
</ParamField>

<ParamField body="callbackUrl" type="string">
  URL to redirect the customer after payment (success or failure). The redirect will include `reference` and `status` as query parameters.
</ParamField>

<ParamField body="description" type="string">
  Optional description shown on the checkout page (max 500 characters)
</ParamField>

<ParamField body="metadata" type="object">
  Additional key-value pairs to attach to the transaction (e.g., order ID, cart ID)
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  Indicates if the request was successful
</ResponseField>

<ResponseField name="message" type="string">
  Response message
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="properties">
    <ResponseField name="reference" type="string">
      Unique transaction reference — use this to verify the transaction later
    </ResponseField>
    <ResponseField name="checkout_url" type="string">
      The hosted checkout page URL. Redirect your customer here to complete payment.
    </ResponseField>
    <ResponseField name="status" type="string">
      Always `pending` at this stage
    </ResponseField>
  </Expandable>
</ResponseField>

## Callback Redirect

After the customer completes (or fails) payment, they are redirected to your `callbackUrl` with the following query parameters:

```
https://yoursite.com/payment/callback?reference=ORD-12345&status=successful
```

| Parameter | Description |
|-----------|-------------|
| `reference` | The transaction reference |
| `status` | `successful` or `failed` |
| `message` | Error message (only present when `status` is `failed`) |

<Warning>
  Do not rely solely on the callback redirect to confirm payment. Always verify the transaction server-side using the [Verify Transaction](/api-reference/verify-transaction) endpoint before fulfilling the order.
</Warning>

## Verifying the Transaction

After the customer is redirected back, verify the transaction on your server:

```bash
curl "https://api.rollapay.com/transaction/verify/ORD-12345" \
  -H "Authorization: Bearer sk_live_your_secret_key"
```

See [Verify Transaction](/api-reference/verify-transaction) for full details.

## Webhooks

In addition to the callback redirect, you can configure webhooks to receive real-time notifications when a transaction status changes. This is recommended for reliable payment confirmation.

See [Webhooks](/api-reference/webhooks) for setup instructions.

## Test Mode

Use your `sk_test_*` secret key to create test checkout sessions. Test transactions use sandbox processors and test cards.

See [Test Cards](/api-reference/test-cards) for available test card numbers.
