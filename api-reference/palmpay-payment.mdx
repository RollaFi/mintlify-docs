## Overview

Accept payments funded directly from a customer's PalmPay wallet balance. You initiate the payment, we return a `payment_url`, and the customer authorises the debit on PalmPay's own checkout page before returning to you.

**Currencies:** `NGN`. The API does not restrict the currency itself — which ones you can charge depends on what PalmPay has enabled for your account. Contact support to confirm.

Each wallet provider is its own channel (`palmpay`, and others as they are added) rather than one generic `wallet` channel, since the wallets are not interchangeable — a PalmPay balance can only be debited by PalmPay.

<Note>
  Unlike `card` or `mobile_money`, this channel needs **no extra object** in the request. There is no card to collect and no wallet number to supply — the customer identifies and authenticates themselves on PalmPay's page.
</Note>

<Warning>
  The response status is `requires_action`, not `pending`. You **must** send the customer to `data.payment_url` — the payment cannot complete until they authorise it there.
</Warning>

## Authentication

All requests must include your secret API key in the Authorization header:

```
Authorization: Bearer sk_live_your_secret_key
```

<Note>
  Use `sk_test_*` keys for testing and `sk_live_*` keys for production.
</Note>

## Request Body

<ParamField body="reference" type="string">
  Optional custom transaction reference. If not provided, a unique reference will be auto-generated (e.g., `TXN_gGbEEvK25eVgmgrf`). Must be globally unique across all transactions.
</ParamField>

<ParamField body="amount" type="number" required>
  The payment amount (e.g., 100 for 100 units of the currency). PalmPay rejects NGN amounts below **100 NGN**.
</ParamField>

<ParamField body="currency" type="string" required>
  Three-letter ISO currency code, e.g. `NGN`. Must be a currency PalmPay has enabled for your account.
</ParamField>

<ParamField body="channel" type="string" required>
  Must be `palmpay`
</ParamField>

<ParamField body="customer" type="object" required>
  Customer information
  <Expandable title="properties">
    <ParamField body="email" type="string" required>
      Customer's email address
    </ParamField>
    <ParamField body="name" type="string">
      Customer's full name
    </ParamField>
    <ParamField body="phone" type="string">
      Contact phone number. Where supplied, it is pre-filled on PalmPay's checkout page to save the customer typing it. Max 20 characters.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="callbackUrl" type="string" required>
  URL to return the customer to once they finish on PalmPay's page. Query parameters `reference` and `status` (successful/failed) will be appended.
</ParamField>

<ParamField body="description" type="string">
  Optional description for the payment (max 500 characters). Shown to the customer on the checkout page.
</ParamField>

<ParamField body="metadata" type="object">
  Additional key-value pairs to attach to the transaction (e.g., order ID)
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  Indicates if the request was successful
</ResponseField>

<ResponseField name="message" type="string">
  Response message
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="properties">
    <ResponseField name="reference" type="string">
      Unique transaction reference or your custom reference if provided
    </ResponseField>
    <ResponseField name="status" type="string">
      Transaction status. `requires_action` — the customer must authorise the payment at `payment_url`.
    </ResponseField>
    <ResponseField name="payment_url" type="string">
      PalmPay's hosted checkout URL. Redirect the customer here.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  The initiate response is intentionally minimal. To see the decline reason or any other detail, call [Verify Transaction](/api-reference/verify-transaction).
</Note>

## Next Steps

After initiating a PalmPay payment, the response status will be `requires_action`. Here's how the flow works:

### 1. Redirect the customer
Send the customer to the `payment_url` returned in the response. This is PalmPay's hosted checkout page.

### 2. Customer authorises the payment
The customer signs in to PalmPay and approves the debit from their balance. This happens entirely on PalmPay's page — you never handle their credentials.

### 3. Customer returns to your callbackUrl
Once they finish, the customer is returned to the `callbackUrl` you supplied.

<Warning>
  Do not treat the return to your `callbackUrl` as proof of payment. The customer can close the tab before it fires, and the URL can be visited directly. Always confirm with Verify Transaction or wait for the webhook.
</Warning>

### 4. Poll for payment confirmation
Poll the [Verify Transaction](/api-reference/verify-transaction) endpoint every 3-5 seconds. Once `status` changes to `successful`, the payment is complete.

### 5. Webhook notification
You will also receive a [webhook](/api-reference/webhooks) notification when the payment is confirmed. This is the authoritative signal — it is only sent after we have confirmed the outcome directly with PalmPay.

<Note>
  Orders expire if the customer does not complete payment in time — 30 minutes by default. An expired order cannot be resumed; initiate a new transaction instead.
</Note>
